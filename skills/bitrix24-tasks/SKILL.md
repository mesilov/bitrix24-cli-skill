# Задачи Битрикс24 через b24cli

Транспорт — [mesilov/bitrix24-cli](https://github.com/mesilov/bitrix24-cli).
Все операции выполняются через публичные команды `b24cli`. Скилл описывает
их параметры и результаты. Карта для **0.2.0** сверена 14.10.2026 по `dev`
(`1ed4422a8d7a33138134d6a8763594820c75c256`): 56 публичных команд.
Источник справки и границы RC — в [контракте транспорта](references/transport.md).
Значения полей, ID и сроки задаются пользователем либо уже настроенным
профилем CLI; скилл не придумывает собственные defaults.
Для выполнения нужен установленный `b24cli` и доступ к shell; для запросов
к порталу — настроенный webhook.

## Подключение и выбор команды

1. Найди `b24cli` в PATH или используй известный путь к бинарю. Проверь
   `b24cli --version`, `b24cli --help`, `b24cli list --raw` и
   `b24cli ИМЯ_КОМАНДЫ --help`. `--about` показывает сведения о сборке без подключения.
   Если доступен `doctor:problem-trajectory`, один раз за запуск проверь
   `--action status --json` и следуй [правилу weekly предложения](references/problem-trajectories.md).
   При analysisDue=false не отвлекай пользователя; при true предложи один пакетный разбор.
2. Прочитай [контракт транспорта](references/transport.md) для подключения,
   формата результата, пагинации и ошибок. Выбирай подключение явно:
   `--env-file PATH` для dotenv или `--profile NAME` для сохранённого профиля.
   Эти опции взаимоисключающие. Не рассчитывай на поиск dotenv в текущем каталоге.
3. Выбери команду по [карте команд CLI](references/commands.md). Используй полное
   имя с двоеточиями, например `task:show`. Карта привязана к проверенной
   версии 0.2.0: 43 команды задач, 4 пользователей, 5 подключений, 1 doctor
   и 3 служебные команды. Возможности установленного бинаря уточняй его справкой.
   Для статусов/результатов, локальных вложений, тегов, пользовательских полей
   и интерпретации длительностей прочитай [рабочие сценарии](references/task-workflows.md).
4. Выполняй команды с `--json`, сохраняй exit code и разбирай `data`, `meta`,
   `error`. Для планирования изменений задач доступен `--dry-run`; он может делать
   проверочные чтения. Удаление в неинтерактивном режиме требует `--force`.

```sh
b24cli --env-file "/absolute/path/to/.env.local" \
  task:show 123 --select id --select title --json
```

## Интерпретация транспорта

- `meta.complete=false` или exit code `3` означает неполный результат.
  `--limit` ограничивает вывод; `--max-scan` ограничивает обход.
- При `meta.outcomeUnknown=true` результат записи неизвестен. Не повторяй
  такую запись автоматически; используй доступные команды чтения для проверки.
- Webhook передаётся через dotenv или окружение, без помещения секрета в
  аргументы, ответ или файлы скилла. Для сложного текста/JSON используй
  предусмотренные `*-file` опции; `-` обозначает stdin.

## Если возможностей CLI недостаточно

Для запросов о дедлайнах и просроченных задачах прочитай
[временные фильтры](references/deadline-windows.md). Сначала проверь наличие
`--deadline-window`, `--overdue` и `--timezone` в справке установленного CLI:
эти параметры входят в карту 0.2.0. Skill передаёт
мнемонику и известный timezone пользователя; интервалы рассчитывает CLI.

Если проверка version/help подтверждает, что для запроса нужна собственная
реализация отсутствующей CLI-возможности, **останови неподдерживаемый путь**.
Несколько штатных CLI-вызовов и обычный разбор JSON сами по себе допустимы.
При наличии doctor следуй [регистрации карточки](references/problem-trajectories.md):
обезличь сценарий и алгоритм словами, вызови публичный doctor:problem-trajectory,
проверь сохранение и сообщи ID/ограничение. Предложи issue сразу либо следующий
пакетный разбор; пользователь не обязан создавать issue для каждого случая.
Без doctor сообщи нехватку команды/параметра и предложи обычный
[issue в bitrix24-cli](https://github.com/mesilov/bitrix24-cli/issues), без обходов.

Не обходи ограничение прямыми HTTP-вызовами, `curl`, SDK, MCP, другим
инструментом или собственным расширением CLI. Не придумывай команды и
не используй нерелевантную команду вместо требуемой операции. Не читай/редактируй
служебные config/карточки и не отправляй feedback собственной обвязкой.
Пакетный анализ и передачу выполняй после соответствующего согласия пользователя;
публичный mock возвращает mocked=true/delivered=false, без реального issue.

Отсутствие credentials или ошибка доступа — ошибка подключения/выполнения,
а не отсутствие возможности CLI. Сообщи её по результату команды.

Пользуйся обычным shell-инструментом своего агента. Скилл не требует
инструментов, расширений или синтаксиса, специфичных для Claude Code,
Codex либо OpenCode.
